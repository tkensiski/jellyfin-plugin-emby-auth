<objective>
Lock in what happens to the login that loses a concurrent first-login race, and reword the Error entry it produces.

Purpose: TEST-05's deterministic half, and D-04. Two simultaneous first logins for one unknown Emby name both reach `CreateUserAsync`; the second gets `ArgumentException` from Jellyfin, and `EmbyAuthenticationProvider.cs:183-187` already refuses the login with 401. The behavior is correct and untested as a race; the message it logs tells the administrator to rename the user on Emby, which is the wrong remedy for a benign collision.
Output: A named unit test that drives the race-loser path deterministically, and one message that states both causes.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted login request -> Jellyfin account creation | An unauthenticated caller chooses the name that reaches `CreateUserAsync`. |
| plugin -> Jellyfin log | A failure names an Emby user name that the caller chose. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-15 | Elevation of Privilege | the losing login adopting an existing account | high | mitigate | The losing login is refused and no lookup by name happens. The prohibition against re-resolving is stated in `must_haves`, and `RefusesTheLosingLogin_WhenTwoFirstLoginsForOneNameRace` asserts `Calls` is exactly one `CreateUserAsync`, so any added lookup or save shows up there. |
| T-04-16 | Denial of Service | an unhandled exception from the race turning a login into HTTP 500 | high | mitigate | The catch converts every exception from `CreateUserAsync` into `AuthenticationException`, which Jellyfin catches. The unit test asserts that exception type, and plan 04-06's burst asserts no response is 500. |
| T-04-17 | Information Disclosure | the reworded Error entry carrying a secret | high | mitigate | The partial takes only the Emby user name and the exception. The test asserts no captured entry contains the password or the hash, and `e2e/90-jellyfin-log.bats` scans the whole Debug-level Jellyfin log for the test password pattern. |
| T-04-18 | Information Disclosure | a caller learning whether a name exists on Emby from the log volume | low | accept | The entry is written to the server log, which only an administrator reads; the caller sees a 401 either way. Log-volume inference by an administrator is not a boundary crossing. |
</threat_model>
