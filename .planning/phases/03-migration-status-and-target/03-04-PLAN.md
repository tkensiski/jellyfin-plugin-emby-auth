<objective>
Turn the destination of a move from a constant into a setting, and rename the three classes and the scheduled task that were named after that constant.

`LoginMethodMove.MoveAsync` takes the target as a parameter. `MoveAfterLogin` and `EmbyMigrationTask` resolve it from the settings, skip the move entirely when the setting says Remain on Emby Login, and log one Error and skip when the setting names a login method Jellyfin no longer reports as enabled — without ever refusing a login, because Emby still checks every password and the safe failure mode here is a user stranded on the Emby method, never a user locked out.

Purpose: this is the generalization the whole phase turns on. Once the destination is a parameter, the settings page can offer it (plan 05), the plugin can refuse a bad one (plan 06), and the end-to-end suite can prove a migration that ends somewhere other than Jellyfin's Default (plan 07).

Output: `MigrationTarget` and `PasswordSetTarget` on the configuration, a target-resolution helper with three outcomes, three renamed classes, a renamed task key, and unit tests for every move class against the SQLite seam.
</objective>
