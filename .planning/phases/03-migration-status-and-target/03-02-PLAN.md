<objective>
Make three statements the plugin already ships stop contradicting the code, and add the one statement it is missing.

Today `EmbyVerifiedPasswords.Record()` assigns the fingerprint into the cache before it writes the file, so a failed write leaves a real in-memory record and the user does move. Three sentences say the opposite: the log message at the end of that class, the XML summary on `Record`, and the Limits entry in `docs/how-it-works.md`. D-09 locks the code's order and D-08 sends the correction to the sentences. That is FPRT-01, and it closes the blocker STATE.md carries from `02-SECURITY.md` O-1.

The same plan adds the visibility guard MIGR-02 asks for, and the blank-password statement DOCS-05 asks for, and verifies that DOCS-01's pointer sentence — already in the file since phase 02 — still resolves.

Purpose: every plan after this one changes where users move to. A reader who trusts a sentence that is false about the current code will draw the wrong conclusion about the new code too.
