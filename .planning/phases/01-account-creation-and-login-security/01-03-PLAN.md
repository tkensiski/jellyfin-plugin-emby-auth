<objective>
Remove the migration behavior that let a saved Jellyfin password decide a login, and rewrite the two end-to-end tests that relied on it.

Purpose: AUTH-01 says that while a user is on the Emby login method, Emby checks every login and the saved Jellyfin hash plays no part in accepting it. One migration-behavior setting contradicted that by design. AUTH-02 removes it with no compatibility path. The removal also orphans two private members, and with warnings as errors plus `AnalysisMode AllEnabledByDefault` the build fails unless all three go in the same change.

Output: a two-member `MigrationMode` enum; an `Authenticate` method with no saved-password branch; a settings page with two options and matching help text; one adjusted settings unit test; and two rewritten e2e tests that prove AUTH-01 against real Emby and Jellyfin containers.
</objective>
