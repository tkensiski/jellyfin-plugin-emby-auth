<objective>
Build the unit-test seam for `EmbyAuthenticationProvider` and close every AUTH-04 failure path behind it, test-first.

Purpose: today a failure inside Jellyfin's user store escapes `Authenticate` as a raw exception. Jellyfin catches only `AuthenticationException` from a login method, so the login returns HTTP 500 instead of a clean 401. The cleanup `DeleteUserAsync` has no exception handling at all. Both gaps are unreachable by test today because the provider reads the static `EmbyAuthPlugin.Instance` for its settings, so this plan creates the seam and the fixes in one vertical slice.

Output: `FakeUserManager` and `FakeCryptoProvider` in `TestDoubles.cs`; a new `EmbyAuthenticationProviderTests.cs` covering all four AUTH-04 failure paths; a settings-source constructor parameter on `EmbyAuthenticationProvider` with its `PluginServiceRegistrator` wiring; unconditional `catch (Exception ex)` on both `UpdateUserAsync` calls; a guarded cleanup delete with a new `LogDeleteFailed`.
</objective>

## Trust Boundaries

| Jellyfin login request → `EmbyAuthenticationProvider.Authenticate` | Untrusted user name and password cross here from an unauthenticated HTTP caller. |
