<assumption_delta_decision>
**Noun:** `manifest`.

**Decision:** `promote`.

**Rationale:** until this phase there was exactly one kind of manifest — the single-version `manifest.json` that `scripts/package.sh build` attaches to each GitHub release. This phase introduces a second, multi-version `PackageInfo[]` document published to GitHub Pages, and the correct move is not to keep both as peers. CONTEXT.md D-02 already settles it: "This settles the fate of the single-version `manifest.json` that `scripts/package.sh` already attaches to each release: it stops being redundant and becomes the rebuild's input." The published multi-version document is promoted to the primary catalog manifest — the one the README gives an administrator, the one Jellyfin fetches, the one PUB-02 is about — and the per-release asset is demoted to a build input of the rebuild. It is not removed, because removing it would remove the rebuild's source of truth for a release's own recorded metadata.

**Consequence carried into this plan:** `scripts/manifest.sh merge` reads exactly the document `scripts/package.sh build` writes, so the two cannot drift into different schemas. A change to `package.sh`'s manifest `jq` call that `manifest.sh` does not understand fails `bats tests/scripts/manifest.bats` rather than silently producing a catalog nobody can install from.

**Invariant test this suggests, and which this plan adopts:** every source directory handed to `merge` appears in the merged document. `tests/scripts/manifest.bats` asserts that the merged `versions[]` length equals the number of source directories, so a future change that silently drops or truncates versions goes red. Plan 06-02 extends the same invariant to `rebuild`: the number of releases the enumeration returned equals the number of entries published.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `CHANGELOG.md` → `meta.json`/`manifest.json` | Repository prose becomes a JSON string value. A quote or backslash in the prose reaches a document a server parses. |
| release zip bytes → the merged manifest's `checksum` field | A value recorded at build time is republished later. Trusting the record rather than the bytes is how a corrupted asset reaches an administrator. |
| the served manifest → Jellyfin's `InstallationManager` | An unauthenticated server-side fetch and an MD5 comparison this repository does not control. |
