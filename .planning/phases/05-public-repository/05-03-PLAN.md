<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a contributor's commit → the repository history | Anything committed is permanent for practical purposes; after PUB-03 it is also world-readable. |
| `.gitleaks.toml` → the gitleaks rule set | The config decides what the scanner is allowed to stay silent about; a wrong entry is a permanent blind spot. |
| `mise run lint` → the pre-commit hook and the CI `lint` job | One task definition is the whole secret-scanning surface for both paths. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-09 | Information Disclosure | git history, about to become world-readable | high | mitigate | `gitleaks git` scans the full history on every `mise run lint`, so the pre-publication requirement is satisfied continuously by the pre-commit hook and CI rather than by one event before the switch |
| T-05-10 | Information Disclosure | `.gitleaks.toml` allowlist scope | high | mitigate | Suppression is by fixture value only; no file, directory, or rule id is exempted, so a real credential committed into `tests/` is still reported. Pinned by three negative acceptance criteria and a read-through in Task 2 |
| T-05-11 | Tampering | the `[tasks.lint]` gitleaks entry | medium | mitigate | The entry carries no flag that changes the exit code on a finding; an acceptance criterion negative-greps `.mise.toml` for exit-code and error-swallowing forms |
| T-05-12 | Repudiation | a scan that silently does nothing | medium | mitigate | Task 2's break-then-restore proof witnesses the scan failing on real findings and then passing, so a scan that is not running cannot be mistaken for a clean one |
| T-05-SC | Tampering | npm/pip/cargo installs | medium | mitigate | gitleaks is the phase's one new tool. It is not an npm/PyPI/crates package: it is a single static Go binary distributed as a GitHub release and resolved through mise's `aqua:gitleaks/gitleaks` backend. `05-RESEARCH.md`'s Package Legitimacy Audit records the verdict OK — canonical repository `github.com/gitleaks/gitleaks`, long-established, no install-time script surface.
