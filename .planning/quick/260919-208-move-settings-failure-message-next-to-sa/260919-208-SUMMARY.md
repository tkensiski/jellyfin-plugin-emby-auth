# Quick Task 260919-208: Move the Settings Failure Message Under Save Summary

**Split the settings-page status element in two, so load/save failure messages render under Save (not under "Migration"), and shipped a CSS rule that visibly dims a disabled Save button.**

## Performance

- **Duration:** not measured (start timestamp not captured at session start; wall-clock work spanned reading context, TDD red/green, e2e run, and the dev-container republish)
- **Completed:** 2026-09-19T08:43:15Z
- **Tasks:** 3/3 completed
- **Files modified:** 4 (`configPage.html`, `configPage.test.js`, `testHelpers.js`, `docs/settings.md`)

## Accomplishments

- Added a new `#EmbyAuthSettingsStatus` `<p role="status">` element, the next sibling after the Save button inside its wrapping `<div>` in `#EmbyAuthConfigForm`. Both `pageshow` and `submit` handlers now write their failure text there; `#EmbyAuthMigrationSummary` is migration-status only.
- Added a scoped `<style>` rule, `#EmbyAuthConfigPage .button-submit[disabled] { opacity: 0.38; cursor: default; }`, shipped inside `#EmbyAuthConfigPage` (the subtree Jellyfin injects).
- The `submit` handler now disables Save synchronously (before the first `.then`), re-enables it next to `Dashboard.processPluginConfigurationUpdateResult(result)` on success, and leaves it disabled after a failed save (recovery is a page reload).
- Added `clearEmbyAuthMigration()`, called from the `pageshow` failure path, so a failed load after a successful one no longer leaves a stale migration summary line and user list on screen (WR-04).
- Extended `tests/js/testHelpers.js` with `settingsStatus(document)` and `pageStyleRules(document)` (reads jsdom's parsed CSSOM from the page's own `<style>` elements).
- Repointed five existing tests at `#EmbyAuthSettingsStatus` and tightened two of them from `assert.match` to `assert.equal` against the full approved message text. Added seven new tests (the plan's task text said "six" but listed seven; all seven were needed to cover the behaviors named in `<behavior>` — see Deviations).
- Updated `docs/settings.md` to state the message now appears under Save and that Save stays off after a failed save until the page reopens.

## Decisions Made

- Save re-enables after a successful save (decided, not deferred, per the plan) — every other Jellyfin dashboard page leaves Save live after a save, and the stale-state risk the locked "disable on attempt" decision guards against does not apply once the page state and saved state agree.
- The disabled-Save style rule uses `opacity: 0.38` rather than a color, because Jellyfin's shipped themes define no disabled-button convention and a hardcoded color would break on the light theme (see the plan's `<research_findings>`, confirmed against the running dev Jellyfin's theme CSS).
